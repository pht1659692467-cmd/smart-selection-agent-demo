## 第一次：只用浏览器

1. 登录GitHub，右上角＋→New repository。
2. Repository name填写 smart-selection-agent-demo 。Visibility选择Public；如果已有同名仓库，不覆盖，先确认目标。此项目文件已带README，不必再自动创建另一份。
3. 创建仓库后选择“uploading an existing file”或Add file→Upload files。
4. 解压部署包，上传本项目内的文件和子目录。必须让index.html位于仓库根目录，不能在根目录再套一层smart-selection-agent-demo文件夹。不要直接上传ZIP作为网站入口。
5. Commit message写“Publish selection workflow demo”，提交到main。Commit就是给这批文件保存一个版本；Push/网页提交把版本放到GitHub。
6. 仓库Settings→Pages→Build and deployment。Source选“Deploy from a branch”，Branch选main，Folder选/(root)，点击Save。
7. 到Actions查看Pages构建部署任务。绿色勾表示成功；失败时点红色任务读具体日志，不必反复重建仓库。
8. 返回Settings→Pages，复制“Your site is live at”后的实际链接。用另一个未登录GitHub的浏览器窗口打开，检查页面与下述链路。
9. 仓库主页右侧About→齿轮，将实际演示地址填入Website，方便面试官从仓库进入。

.nojekyll是空文件，部分Windows窗口不明显。此项目没有特殊目录资源，漏上传它一般不会影响index.html显示，但建议保留。

## 以后修改：仍可只用网页

1. 在本地改公开版本index.html等文件，运行npm test并用npm start预览。
2. 仓库Add file→Upload files，上传修改后的同名文件，提交到main。
3. GitHub Pages会随发布分支更新而重新部署。等待Actions绿色，再刷新实际演示链接。
4. 出现问题时在提交历史查看差异，恢复上一版文件并新建提交。不要删除仓库重来。

## 可选：使用Git命令

如果网页部署已经完成，建议先git clone仓库到一个新目录，不要在现有找回素材总目录初始化并上传全部内容。

    git clone https://github.com/pht1659692467-cmd/smart-selection-agent-demo.git
    cd smart-selection-agent-demo
    # 把修改后的公开版本文件复制进来
    npm test
    git status
    git add index.html README.md
    git commit -m "Update demo"
    git push origin main

首次Git身份认证按GitHub/系统浏览器提示完成；不要把密码或访问Token写入代码、README或聊天。GitHub CLI不是网页部署的前置条件。

## 常见情况

仓库能打开但网站404：先检查Pages是否启用、main是否正确、index.html是否在选定根目录，以及Actions结果。

更新后仍见旧版：先等部署成功，再刷新或用隐私窗口查看。上传文件不等于部署已经完成。

不能在GitHub Pages运行真实后端：Pages托管静态HTML/CSS/JS。未来接入真实Agent/模型时，再部署后端并在服务端保存密钥；这次静态演示不需要后端。
